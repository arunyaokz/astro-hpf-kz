## 能否用 EmDash 管理

可以，技术路线匹配。当前 npm 最新 EmDash 为 **1.3.1**，官方提供[现有 Astro 项目接入指南](https://docs.emdashcms.com/existing-project/)和[Cloudflare 部署指南](https://docs.emdashcms.com/deployment/cloudflare/)。

EmDash 提供内容后台、草稿与发布、媒体管理及[多语言内容关联](https://docs.emdashcms.com/guides/internationalization/)。现有官网使用中、英、俄三语，应保持这三种语言与现有 URL；如以后加哈语，可另外扩展。后台界面的中文翻译完整度须在接入试验中实际核验，不能把“可管理中文内容”当作“后台已完整中文化”。

安装 CMS 不会自动把组件内的文案变成可编辑字段。现有内容分布在 `src/corporate-content.ts`、`src/site-v2.ts`、`src/content/` 与组件中；需要建立内容模型、迁移内容，并让页面读取后台发布数据。现有 `facts.yaml` 的来源、核验标记和三语字段也应保留。

| 官网内容 | 建议接入方式 |
| --- | --- |
| 新闻 / 公司动态 | 优先建立 news 内容集合，保留分类、来源、核验状态及三语对应关系 |
| 服务、路线、公司介绍 | 第二步建立结构化页面字段，沿用现有版式和 URL |
| 图片、封面 | 迁入媒体库，记录替代文本和来源 |
| 公司事实、联系方式 | 保留核验状态与出处，作为结构化设置管理 |
| 页面布局、地图、交互 | 继续由 Astro 代码实现 |

## 推荐实施顺序

1. 从当前本地升级分支另建 CMS 试验分支，先接一个新闻集合。
2. Cloudflare 路线使用 EmDash + 现有 Astro Cloudflare 适配器 + React 后台；D1 存内容，R2 存媒体。另建官网专用资源，按官方指南配置密钥和迁移。
3. 采用按请求渲染的内容页面，让发布生效；结合官方缓存方案减少重复查询。后台需要服务端运行能力，现有纯静态输出需要调整。
4. 本地完成管理员初始化、中文操作界面核验、三语草稿/发布测试及图片上传测试，再接预览环境。尚未配置管理员或创建这些资源。
5. 保留既有 URL、SEO 和公司事实核验机制；确认内容迁移结果后再替换正式站点。俄语、未来哈语新增译文需母语者校对。

官方国际化说明要求默认语言不强制加路径前缀，否则 `/_emdash/admin` 可能 404。应以现有默认英语无前缀、中俄 `/zh/` 和 `/ru/` 路径为基础处理。

本次只评估可行性，尚未实施 EmDash 接入；没有产生 D1/R2 资源或 CMS 运行费用。
